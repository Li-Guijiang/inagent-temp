## 一、OPC 模式定位

**OPC = One-Person Company（一人公司）**。本方案以"1 名交付/运营者 + inAgent 智能体平台 + 5 个标准化技能包"构成一家可独立承接江苏中小制造企业数字化转型项目的小微公司：

- **不养研发团队**：5 个技能包代码与标准库已标准化交付，实施只需"换标准表"即可适配新企业；
- **不养 IT 运维**：inAgent 本地单机部署、免云端订阅，交付后由 inAgent 定时/批量能力自动运转；
- **不依赖大客户销售团队**：以"样板工厂 → 口碑复制"的滚雪球模式覆盖江苏中小集群。

**为什么适配 OPC**：江苏中小制造企业普遍"预算有限、无专职 IT、怕重资产改造"（禾派阁等企业调研反馈），传统系统集成商（SI）动辄 50 万级项目+驻场团队无法覆盖这一长尾市场；OPC 以 10 万级轻量化套餐 + 远程交付，正好填补空白。

## 三、服务模式与交付流程

### 3.1 服务模式：低频轻咨询 + 标准化工具 + 远程运维

| 环节 | 模式 | 说明 |
| --- | --- | --- |
| 交付 | 本地单机部署（inAgent 桌面工作台） | 现场半天完成部署，不碰企业核心网络，安全合规 |
| 实施 | "换标准表即换业务" | 将企业设备/质检/能耗/工艺/追溯标准录入 `inspection_standards.md`，脚本零改动 |
| 验效 | 30 天免费试运行 | 用《降本增效量化指标表》抓实施前后基线对比，产出验效报告 |
| 运维 | inAgent 定时任务 + 远程值守 | 日报/告警自动产生，仅严重/紧急告警人工介入 |
| 收费 | 年费订阅制 | 详见第四节定价策略 |

### 3.2 一人公司的分工（OPC 主理人一人完成）

| 角色 | 具体工作 | 工作量占比 |
| --- | --- | --- |
| 售前咨询 | 拜访企业、痛点确认、方案讲解、报价 | 25% |
| 实施交付 | 标准表录入、部署、联调、操作工培训（半天） | 30% |
| 验效与续约 | 月度回顾、效益报告、续约谈判 | 20% |
| 远程运维 | 处理预警告警、标准库迭代（依赖 inAgent 自动化） | 15% |
| 市场与拓客 | 标杆案例传播、产业园/行业协会渠道 | 10% |

> 一人即可运转的前提：**95% 的数据采集、分析与报告由技能包自动化完成**，OPC 只做"确认标准 + 人工复核告警 + 商务"。

## 七、风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 客户续约率低（行业波动） | 高 | 用《量化指标表》绑定续约依据；多行业客户分散风险（覆盖汽车/纺织/装备等 8 家样本场景） |
| 一人产能瓶颈 | 中 | 技能包自动化 + 标准化模板使交付工时极低；高峰期外协 1 名实施伙伴 |
| 指标承诺兑现风险 | 中 | 报价采用"区间值"，签约前实测基线收敛；免责声明见量化指标表 |
| 大厂降价竞争 | 中 | 主打"本地部署+年费+行业标准库"差异化，避免拼纯价格 |
| 政策/合规变化 | 低 | 部署本地化、数据不出厂，主动对齐智改数转与数据安全要求 |
