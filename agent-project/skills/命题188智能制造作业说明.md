# 命题188 · 智能制造作业说明文档

> **项目名称**：面向江苏智能制造企业的产业级 AI Skill 体系（5 技能包）
> **依据素材**：江苏智能制造 8 家企业调研日志（江苏天钧精密、无锡贝斯特精机、苏州禾派阁、苏州聚晟视、樵弋机器人·江阴、江苏赫伽力、国投融合·无锡、苏州富强）
> **编制时间**：2026-09-22
> **运行环境**：Python 3.12.10 + openpyxl 3.1.5（Windows）

## 一、项目概述

本作业基于江苏智能制造 8 家企业的实地调研成果，针对其中暴露的**共性产业痛点**（P1 质检依赖人工、P4 工艺知识缺失、P5 数据孤岛、设备运维短板、能耗与追溯管理薄弱），设计并实现了 **5 个可独立运行、可扩展对接的产业级 AI Skill 包**，覆盖制造企业"检测—分析—优化—追溯"的业务闭环：

| 序号 | Skill 包 | 业务环节 | 定位 |
| --- | --- | --- | --- |
| 1 | equipment-inspection | 设备运行保障 | 设备日常点检、故障预警、维护建议 |
| 2 | quality-inspection | 质量防线 | 质检指标巡检、质量告警、改进建议 |
| 3 | energy-analysis | 绿色制造 | 能耗基线管理、能耗告警、节能建议 |
| 4 | process-optimization | 工艺能力 | 工艺参数监控、工艺偏离告警、改进建议 |
| 5 | quality-traceability | 全程溯源 | 追溯体系监控、断链告警、体系改进 |

**设计亮点**：5 个包共用一套目录结构与脚本框架，"标准知识库"即业务差异点，实现"换表即换业务"的最小化定制；均满足**可直接运行、产出标准产物（Markdown 日报/告警 + Excel 台账）**的可验证要求。

## 二、总体架构

### 2.1 统一目录结构（各 Skill 包一致）

```
skills/<skill-name>/
├── SKILL.md                # 技能说明（用途/触发/流程/参数/扩展点）
├── scripts/
│   ├── data_fetch.py       # 数据采集（demo 模拟模式 + mcp 真实模式双通道）
│   ├── analysis.py         # 分析算法（四级状态判定：正常/预警/严重/紧急）
│   └── report_gen.py       # 报告生成（日报、分级告警文件、Excel 台账同步）
├── templates/
│   ├── daily_report.md     # 日报模板（{{占位符}} 渲染）
│   └── alert_template.md   # 告警模板（按等级分级生成）
└── docs/
    └── inspection_standards.md  # 标准知识库（analysis.py 的唯一判定依据）
```

### 2.2 三阶段流水线（每个包均一致）

```
data_fetch.py ──> device_data.JSON ──> analysis.py ──> analysis_result.JSON ──> report_gen.py
  (采集数据)        (中间产物)          (阈值判定)         (中间产物)            (日报+告警+台账)
```

1. **数据采集**：默认 `--source demo` 生成可复现的模拟数据（seed=42），预留 `--source mcp` 真实数据通道。
2. **阈值分析**：解析标准知识库表格，按"由内向外"原则逐项判定四级状态，求设备级最严重等级。
3. **报告生成**：渲染 Markdown 日报、按等级拆分告警文件，并通过 openpyxl 逐项追加 Excel 台账。

### 2.3 统一判定规则

| 判定区间 | 状态 | 说明 |
| --- | --- | --- |
| 落在 `[正常下限, 正常上限]` | 正常 | 持续保持 |
| 超出正常区，落在 `[预警下限, 预警上限]` | 预警 | 48h 内复核 |
| 超出预警区，落在 `[紧急下限, 紧急上限]` | 严重 | 当班处理 |
| 超出紧急区 | 紧急 | 立即停机/处置 |

## 三、各 Skill 包详述

### 3.1 equipment-inspection（设备点检）
- **触发**：用户说"设备点检/检查设备状态"；每日定时；数据异常。
- **覆盖**：12 台设备、34 项点检参数。
- **对接痛点**：贝斯特五轴/珩磨停机即影响头部客户交付、天钧焊接设备超温致焊缝缺陷、赫伽力AGV续航、国投融合机房等设备运维痛点。
- **演示告警**：焊枪温度→预警；主轴振动→严重；PLC 断连→紧急。
- **产物**：`daily_report_*.md` + `alert_<等级>_*.md` + `inspection_ledger.xlsx`。

### 3.2 quality-inspection（质量巡检）
- **触发**：用户说"质量巡检/检查产品质量"；每日/每班定时；质检数据异常。
- **覆盖**：11 个质检对象、28 项质检指标（漏检率、误检率、CPK、合格率、检出率等）。
- **对接痛点**：贝斯特人工抽检漏检、天钧焊缝质检难、樵弋崩边漏检、聚晟视/禾派阁误检漏检。
- **演示告警**：焊缝漏检率→预警；CPK→严重；一次组合格率→紧急。
- **产物**：`quality_report_*.md` + `quality_alert_<等级>_*.md` + `quality_ledger.xlsx`。

### 3.3 energy-analysis（能耗分析）
- **触发**：用户说"能耗分析/节能分析"；日/周/月定时；能耗异常。
- **覆盖**：12 个能耗单元、23 项能耗指标（单位电耗、待机功耗、负载率、泄漏率、PUE、充电效率等）。
- **对接痛点**：贝斯特高值设备能耗、天钧焊接产线能耗、赫伽力AGV/机器人续航、富强气路泄漏、国投融合机房 PUE。
- **演示告警**：五轴待机功耗→预警；复合机器人日耗电→严重；气源泄漏率→紧急。
- **产物**：`energy_report_*.md` + `energy_alert_<等级>_*.md` + `energy_ledger.xlsx`。

### 3.4 process-optimization（工艺优化）
- **触发**：用户说"工艺优化/工艺参数分析"；日/批/月定时；工艺参数偏离。
- **覆盖**：11 个工艺单元、22 项工艺参数（焊接电流/速度/热输入、转速、节拍、磨损率、算法延迟等）。
- **对接痛点**：天钧焊接工艺参数分散难沉淀、贝斯特 CAD/CAM/CAE 经验依赖、聚晟视算法参数、樵弋成像参数、富强非标工艺。
- **演示告警**：焊接速度偏差→预警；刀具磨损率→严重；工艺稳定率→紧急。
- **产物**：`process_report_*.md` + `process_alert_<等级>_*.md` + `process_ledger.xlsx`。

### 3.5 quality-traceability（质量追溯）
- **触发**：用户说"质量追溯/产品溯源"；日/批/月定时；追溯断链。
- **覆盖**：10 个追溯单元、19 项追溯指标（覆盖率、赋码率、关联率、归档及时率、锁定率等）。
- **对接痛点**：国投融合平台数据溯源、天钧/贝斯特批次追溯、数据孤岛痛点 P5、"一物一码全程可溯"行业要求。
- **演示告警**：追溯覆盖率→预警；缺陷数据关联率→严重；工单批次锁定率→紧急。
- **产物**：`traceability_report_*.md` + `traceability_alert_<等级>_*.md` + `traceability_ledger.xlsx`。

## 六、扩展与真实部署对接

### 6.1 三处标准化的扩展点

| 扩展需求 | 修改位置 | 说明 |
| --- | --- | --- |
| 新增业务指标 | `docs/inspection_standards.md` 表末尾追加一行 | 脚本零改动，即改即用 |
| 对接真实数据源 | `scripts/data_fetch.py::_fetch_from_mcp` | 替换为对设备/质检/能耗/工艺/追溯 MCP 或 MES/SCADA 的调用 |
| 对接企业微信告警 | `scripts/report_gen.py::_send_wecom_alert` | 接入企业微信 MCP 后自动推送严重/紧急告警 |

### 6.2 安全生产与合规提示
- 演示模式数据仅用于链路演示与教学，**严禁用于实际生产判定**。
- 标准阈值为企业调研参考值，正式上线前应由设备/质量/工艺/能源工程师结合厂商手册与体系文件校准。
- 告警处置、召回冻结等动作涉及生产安全与商业责任，须经人工复核确认。
